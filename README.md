# CareerCopilot（暂定代号）

> 面向中国大陆 1～5 年经验技术求职者的 AI 求职助手。当前仓库只包含经过需求确认的产品与实施规格，不代表功能已经开发、部署或通过 Beta 验收。

## 1. 项目目标

CareerCopilot 帮助求职者完成以下闭环：

1. 上传 PDF/DOCX 简历并确认结构化事实。
2. 创建最多 3 个独立求职方案。
3. 每日从合规公开来源发现新岗位。
4. 使用硬条件、向量检索和 AI 对岗位进行可解释匹配。
5. 对高价值岗位执行受控的多 Agent 深度分析。
6. 在不虚构事实的前提下生成岗位定制简历。
7. 对缺失技能提供免费、可验证的学习入口。

第一阶段在 Windows + WSL2 + Docker Desktop 本地运行；本地验收通过后，再部署到单台阿里云 ECS，邀请 20～50 名用户进行封闭 Beta。

## 2. 已锁定的关键边界

- 用户：18 岁以上、1～5 年经验的技术求职者。
- 岗位：AI 应用开发、Python 后端、Java 后端、前端、数据分析/数据工程、软件测试/测试开发。
- 城市：北京、上海、深圳、杭州、广州、成都。
- 用工：只支持全职；外包、派遣、驻场默认排除，用户可主动开启。
- 岗位来源：第一批以 BOSS 公开可合规访问内容和企业官网为目标；受限时必须降级为搜索跳转或用户导入，不得绕过登录、验证码或反爬措施。
- 技术：FastAPI + Next.js/React + PostgreSQL/pgvector + Redis + Celery + OSS。
- 模型：DeepSeek 为主要生成模型，通义千问为备用/离线对照，阿里云百炼提供 Embedding。
- Agent：LangGraph 仅编排 AI 助手、多 Agent 分析与人工确认；确定性业务保持普通 Python 服务。
- 隐私：完整简历发送给每个第三方模型前必须分别、主动、明确授权；默认不勾选。
- 交付：响应式 Web；站内通知；不自动投递、不管理申请进度、不接支付。

## 4. 推荐实施顺序

```mermaid
flowchart LR
  A["项目脚手架与本地基础设施"] --> B["认证、授权与数据生命周期"]
  B --> C["简历解析与事实库"]
  C --> D["岗位连接器与标准化"]
  D --> E["规则、向量与评分"]
  E --> F["AI 助手与多 Agent"]
  F --> G["定制简历与导出"]
  G --> H["管理后台、评测与本地验收"]
```

不要从多 Agent 界面开始开发。没有可靠的事实库、岗位来源、硬条件和评测集时，多 Agent 输出不可验证。

## 5. 文档优先级

出现冲突时按以下顺序处理：

1. 安全、隐私、数据来源硬边界。
2. PRD 中标记为 MUST 的需求与 Non-goals。
3. API、数据模型和验收门槛。
4. 页面表现与实现细节。

任何会扩大数据使用范围、引入新第三方、绕过外部平台限制、自动执行不可逆操作或改变 Beta 预算的决定，都必须先形成 ADR 并由项目负责人确认。

## 6. 完成口径

- “设计完成”：本仓库文档齐全且冲突检查通过。
- “本地实现完成”：代码、迁移、自动化测试和本地端到端证据齐全。
- “可部署”：镜像、配置、备份、恢复、健康检查和安全检查齐全。
- “Beta 就绪”：真实云环境、真实来源、模型费用、删除/导出、20～50 人容量及人工评测均通过。

本地测试通过不等同于云端或 Beta 就绪；文档、代码、测试和生产证据必须分开陈述。

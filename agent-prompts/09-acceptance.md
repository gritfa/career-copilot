# 阶段 9：系统验收、本地交接与 Beta 准备

前置：阶段1～8均有验收证据。阅读 `docs/09-testing-evaluation.md` 和 `docs/11-delivery-plan.md` 全文。

## 目标

把分散功能验证为完整本地 MVP，完成60组人工评测、安全测试、运行手册和真实未验证边界说明。不要在没有云端证据时宣称 Beta 已上线。

## 必须执行

- 从干净环境启动全部容器并应用迁移。
- 后端/前端格式、lint、类型、单元、集成、构建、OpenAPI、迁移、依赖/密钥扫描。
- Playwright 跑通登录 → 上传 → 确认事实 → 方案 → 推荐 → 深度分析 → 定制简历 → 导出 → 反馈 → 数据导出/注销。
- 60组人工标注评测：Top10 ≥70%、硬条件误放 <1%、证据100%、虚构0。
- 公平性对偶、Prompt injection、模型授权/fallback、管理员越权、日志敏感信息、删除完整性测试。
- DOCX/PDF 渲染视觉检查。
- 来源能力矩阵和至少7天稳定性所需的监控/报告机制；若没有7天真实运行，只标未验证。
- 备份/恢复、预算熔断、模型/来源降级桌面演练。

## Gate 规则

任何必需测试、任务、覆盖或门槛失败时，验收脚本必须非零退出。不得用“总测试数量很多”掩盖关键失败。不得把合成 Adapter、Mock、静态 Docker 或本地单机结果称为真实供应商/阿里云/20～50人 Beta 证据。

## 最终交付

1. 已完成需求 ID 与证据索引。
2. 所有命令、退出码、测试和评测摘要。
3. Git 状态、迁移版本、镜像/依赖锁定信息。
4. 安全、隐私、来源和成本检查结果。
5. 明确分栏：设计完成 / 已实现 / 本地验证 / 云端未验证 / Beta 未验证。
6. 阻断项和下一步最短路径。

只有本地 Definition of Done 全部满足时称“本地 MVP 完成”；云端和 Beta 需要 `docs/09-testing-evaluation.md` 第13节的独立证据。

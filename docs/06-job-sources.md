# 06. 岗位来源、采集与标准化

## 1. 目标和硬边界

第一批来源目标：

- BOSS 直聘公开且允许访问的岗位入口。
- 互联网大型企业与成长型科技公司的官方招聘网站。
- 用户主动粘贴的岗位链接或职位描述。

第二批候选：拉勾、猎聘。任何来源都必须先完成能力调查，不能把“浏览器能打开”视为“允许自动采集”。

禁止：绕过登录、验证码、频率限制、付费墙、设备验证、签名接口、反爬措施；禁止使用用户账号在后台自动操作。

## 2. 来源能力矩阵

开发任何连接器前提交并评审以下矩阵：

| 字段 | 说明 |
|---|---|
| 来源与官方域名 | 防止仿冒和错误入口 |
| 来源类型 | 企业官网/招聘平台/用户导入 |
| 访问政策与检查日期 | robots、服务条款、公开说明 |
| 允许方式 | API、公开 HTML、搜索跳转、仅用户导入 |
| 登录/验证码要求 | 出现即停止自动化路径 |
| 允许频率 | 连接器的硬限速 |
| 可获得字段 | 标题、公司、城市、薪资、发布时间等 |
| 稳定主键 | source_job_id 或 URL 规则 |
| 增量能力 | 更新时间、分页、失效判断 |
| 数据质量样本 | 至少 20 个真实岗位的字段完整度 |
| 降级路径 | 关闭连接器后用户仍如何使用 |
| 负责人和复查日期 | 条款/页面变化后的复核 |

## 3. 首批企业官网选择

不在设计阶段固定公司名单。开发者按以下标准产生 20～30 家候选，先验收前 10 家：

- 覆盖六个目标城市和六类岗位。
- 官网公开、岗位真实性和发布时间较清晰。
- 无需登录即可查看岗位详情。
- 存在稳定列表/详情页或官方开放接口。
- 有合理增量和失效检测方式。
- 大厂与成长型科技公司混合，不让单一公司占据推荐池。

每个连接器单独配置和停用；不得为了凑数量降低合规与质量标准。

## 4. 连接器接口

建议端口：

```python
class JobSourceAdapter(Protocol):
    source_key: str

    async def discover(self, cursor: str | None) -> DiscoveryPage: ...
    async def fetch_detail(self, ref: SourceJobRef) -> RawJobSnapshot: ...
    async def check_validity(self, ref: SourceJobRef) -> ValidityResult: ...
    def policy(self) -> SourcePolicy: ...
```

Adapter 只能返回原始快照和来源元数据；标准化、去重和匹配属于独立服务。连接器不得直接写 Recommendation。

## 5. 采集调度

- 全局每天一次。
- 各来源使用随机抖动，避免同一时间集中访问。
- 失败采用有限指数退避；验证码/禁止访问立即熔断。
- 已推荐岗位每天低成本检查有效状态，但遵守来源频率。
- 管理后台可暂停来源、单次运行、查看最近成功和失败原因。

成功退出必须满足明确不变量：任务失败、字段覆盖不达标或来源受限时，运行状态不能标记为成功。

## 6. 不可变来源证据

每次详情获取保存：

- 原始 URL、获取时间、HTTP 元数据。
- 内容哈希和不可变快照存储 key。
- 解析器/标准化器版本。
- 原始发布时间与最后观察时间。

人工修正写入派生层，不能覆盖原始快照。任何匹配报告都应能定位到当时使用的快照版本。

## 7. 标准化

### 7.1 职位分类

映射到六个 `role_family`，同时保存原始标题。无法可靠分类时标记 `unknown`，不得强行分配。

### 7.2 城市

统一行政区代码和显示名；“全国/远程/多个城市”分开处理。第一版推荐范围只包含六个城市，办公方式由用户选择。

### 7.3 薪资

- 统一为 CNY 月薪最小/最大值。
- 单独保存 13/14/16 薪等薪数。
- 日薪、年薪或面议保留原始表达与换算置信度。
- 缺失/面议不得伪造数值，也不能错误通过最低薪资硬过滤；应作为不确定项展示。

### 7.4 经验和学历

- 解析最小/最大经验年限及“应届/不限”。
- 学历区分 required、preferred、unknown。
- 规则无法判断时交给结构化 AI 辅助，但必须保留原文和置信度。

### 7.5 用工与外包

只接受全职岗位。外包、派遣、驻场使用规则 + AI 风险信号识别，输出证据和置信度；用户未开启时默认过滤，但不把不确定判断宣传为事实。

## 8. 去重

分层去重：

1. 相同来源 ID/URL：确定性重复。
2. 公司规范名 + 标准职位 + 城市 + 发布时间：候选重复。
3. 职责与要求文本相似度：辅助判断。
4. 高置信度自动合并；中等置信度进入人工/管理员队列。

合并后企业官网优先作为主来源，仍保留全部来源、各自发布时间和申请链接。来源更新时生成新版本，不静默覆盖历史证据。

## 9. 时效与失效

- 默认只推荐发布/首次发现 30 天内的岗位。
- 越新排序越高。
- 404、明确下架或官网删除 → inactive。
- 登录墙/临时网络错误 → unknown，不立即判定下架。
- 岗位重新发布且内容实质变化 → 新版本或新 canonical job，规则需可测试。

## 10. BOSS 降级策略

若没有明确允许的自动访问方式：

1. 不实现后台爬虫。
2. 根据用户方案生成原平台搜索入口。
3. 用户可粘贴岗位 URL 或正文导入。
4. 系统分析用户提供内容并保留来源链接。
5. 管理后台显示该来源为 `link_out/import_only`，不能显示绿色“采集正常”。

## 11. 来源验收

每个连接器至少通过：

- 20 个真实岗位样本字段覆盖评审。
- 增量、分页、重复、下架、空结果和结构变化测试。
- 限速、熔断、超时和错误分类测试。
- 来源政策/访问方式证据留档。
- 不含硬编码账号、Cookie、验证码绕过。
- 失败时关闭单个来源不影响其他来源和用户导入。

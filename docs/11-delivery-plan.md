# 11. 10～12 周实施计划

> **2026-07-30 修订（ADR-002）**：ADR-001 D1 对第 5 周的裁剪（「连接器非阻断、供给不足不阻塞
> Beta」）作废。真实岗位来源 Spike 是 MVP 硬门槛：至少一个真实合规来源端到端产出真实岗位并
> 进入推荐、形成书面 Spike 结论之前，不得宣称「完整本地 MVP」或「Beta 就绪」；用户导入仅为
> 降级/补充路径。见 [ADR-002](13-adr-002-supply-spike-gate.md)。

## 1. 实施方式

- 一名偏 Python 的全栈开发者。
- 模块化单体，分阶段可运行、可测试、可演示。
- 每阶段单独提交证据，禁止最后一周集中集成。
- 先使用合成数据；真实简历仅限项目负责人且经过正常授权流程。

## 2. 里程碑

### 第 1 周：脚手架与本地基础设施

交付：

- monorepo、FastAPI、Next.js/TypeScript。
- Docker Compose：PostgreSQL/pgvector、Redis、Mailpit、存储替身。
- Alembic、配置、结构化日志、健康/能力端点。
- CI：后端/前端/迁移/构建/密钥扫描。

验收：空环境可复现启动；真实 PostgreSQL/Redis 集成测试通过。

### 第 2 周：认证、授权与隐私骨架

交付：

- 邀请码、邮箱免密登录、会话、RBAC、18岁确认。
- DeepSeek/Qwen 分别授权和撤回。
- 审计事件、7天注销状态机、隐私页面骨架。

验收：邮箱枚举/重放/越权测试；撤回后 Gateway 拒绝完整数据。

### 第 3 周：简历解析与事实库

交付：

- PDF/DOCX 上传、校验、私有存储 Adapter。
- 文本提取、候选事实 Schema、用户确认界面。
- 事实来源、证据和版本。

验收：合成文件成功/失败路径；没有确认的事实不能进入最终库。

### 第 4 周：求职方案与岗位领域模型

交付：

- 最多3个方案、六类岗位、六城市、薪资/办公/公司偏好。
- 岗位来源、快照、标准化、CanonicalJob 数据模型。
- 用户链接/正文导入。

验收：硬约束、薪资三态、学历 required/preferred 测试。

### 第 5 周：首批来源连接器（ADR-002：本周目标为 MVP 硬门槛，不得降级）

交付：

- 来源能力矩阵和首 10 家候选评审。
- 至少 2 个真正允许的企业官网连接器作为纵向样例。
- 每日 Celery 调度、限速、熔断、增量、下架。
- BOSS link-out/import-only 降级路径。

验收：每连接器20样本；失败不能假绿；来源可独立关闭。

### 第 6 周：Embedding、去重和基础匹配

交付：

- 阿里云 Embedding Gateway、pgvector 索引版本。
- 去重、硬过滤、综合评分、证据组件。
- 每方案20个推荐、等级和反馈。

验收：60组标注集首轮基线；硬条件误放测试和公平性对偶测试。

### 第 7 周：标准 AI 分析与多 Agent

交付：

- DeepSeek Model Gateway、Qwen 授权备用。
- LangGraph 角色、结构化输出、质量审查和一次修复。
- 自动3次 + 手动3次账号级额度、异步进度和站内通知。

验收：失败降级、预算熔断、Prompt injection、无思维链泄露。

### 第 8 周：AI 助手与人工确认

交付：

- 只读工具、草稿工具、pending action。
- 事实写入/最终版本前审批。
- 90天聊天保留和单独删除。

验收：工具越权、任意 URL/SQL、批准/拒绝/过期恢复测试。

### 第 9 周：简历定制、模板和导出

交付：

- 统一事实库、方案基础版、岗位定制版。
- 修改对比、逐项确认、每天3次限制。
- 2～3套单栏模板、DOCX/PDF 导出。

验收：事实引用 100%；视觉渲染无重叠/截断；虚构事实为0。

### 第 10 周：管理后台与隐私闭环

交付：

- 邀请码、来源、任务、能力、费用、匿名指标、反馈。
- 用户限时支持授权。
- 数据导出、单份删除、注销恢复和到期清理。

验收：管理员默认无正文权限；OSS/DB/向量/派生清理清单通过。

### 第 11 周：系统评测与安全加固

交付：

- 60组完整人工标注、权重校准。
- 全量 CI/E2E、安全测试、日志敏感扫描。
- 本地运行手册、备份恢复演练。

验收：PRD Beta 前本地门槛全部通过或明确 No-go。

### 第 12 周：缓冲与云端 Beta 准备

交付：

- 修复高优先级缺陷。
- ECS/OSS/域名/HTTPS 部署清单和成本复核。
- 隐私政策、用户协议、Beta 访谈脚本。

注意：若尚未购买域名或部署云端，第12周只能称“本地 MVP 完成”，不能称“Beta 已上线”。

## 3. 阶段门禁

每阶段结束必须提交：

- 需求 ID → 代码/测试映射。
- Git 状态和 commit。
- 执行命令、退出码和摘要。
- 失败/未验证清单。
- UI/文件产物的截图或渲染证据。
- 数据来源/供应商能力证据（如适用）。

## 4. 关键风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| BOSS 无法合规自动采集 | 岗位覆盖下降 | 企业官网 + link-out + 用户导入，能力真实标识 |
| 单人开发范围过大 | 延期 | 按阶段门禁，先2个纵向连接器，不提前扩展 |
| 多 Agent 成本/延迟 | 超预算、体验差 | 账号级3+3、分级模型、异步、熔断 |
| 简历解析差异 | 事实错误 | PDF/DOCX 边界、候选事实必须确认 |
| 模型虚构 | 信任与合规风险 | fact ID、确定性导出校验、质量审查、0容忍 Gate |
| 单机故障 | Beta 中断 | 明确非高可用、每日备份、恢复演练 |
| 外部条款变化 | 连接器失效 | 能力矩阵复查、独立停用、降级路径 |

## 5. 开发前置条件

- Docker Desktop + WSL2。
- GitHub 私有仓库。
- DeepSeek、阿里云百炼、OSS 的开发凭据（通过环境变量/密钥管理，不在聊天发送）。
- 测试邮箱和本地 Mailpit。
- 项目负责人自己的 PDF/DOCX 简历，仅在授权功能完成后使用。
- 人工标注 60 组样本的时间安排。

## 6. 变更控制

新增第一版范围前回答：

1. 是否改变目标用户/闭环？
2. 是否引入第三方或新数据用途？
3. 是否超过500元/月或10～12周？
4. 是否降低可解释、可测试或删除能力？
5. 应删除/延期哪个现有范围？

没有明确取舍的新增需求默认进入 Backlog，不进入当前里程碑。

## 7. 最终交接物

- 源码、锁文件、迁移、OpenAPI。
- Docker/部署配置与 `.env.example`。
- 自动化测试、60组评测集和报告。
- 来源能力矩阵、模型/提示词版本清单。
- 安全、备份、恢复、发布、回滚运行手册。
- 隐私/用户协议草案和专业复核清单。
- 本地完成证据与仍未验证的云端/Beta 边界。

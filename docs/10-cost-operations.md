# 10. 成本、运维与故障降级

## 1. 预算目标

- 本地阶段：除必要模型/Embedding API 外尽量接近 0。
- 封闭 Beta：每月总运行成本不超过 500 元。
- 规模：20～50 名邀请用户。

以下为预算框架，不是供应商报价。实施和上线前必须查看阿里云、DeepSeek 等官方实时价格并更新本文件。

## 2. 预算分配建议

| 项目 | 20人 Beta 月度目标 | 50人 Beta 月度目标 | 控制方式 |
|---|---:|---:|---|
| 单台 ECS | 80～160 | 100～200 | 合适规格、年度优惠需单独评估 |
| OSS + 请求 + 流量 | 5～20 | 10～40 | 生命周期、短时下载、限制文件大小 |
| DeepSeek | 30～100 | 80～180 | 分级模型、配额、缓存、批处理 |
| 阿里云 Embedding/Qwen 备用 | 10～50 | 20～80 | 去重、只嵌入变化内容、备用不常态调用 |
| 域名/证书摊销 | 5～20 | 5～20 | 证书优先合规免费方案 |
| 备份/邮件/监控 | 10～40 | 20～60 | 最小化、滚动保留 |

目标不是把所有预算花完，而是用真实账单校准单活跃用户成本。若托管数据库等方案导致超过 500 元，Beta 仍使用单机 Docker，明确其非高可用边界。

## 3. 调用预算

每次 Model Gateway 调用预估并检查：

- 用户当日操作额度。
- 操作类型预算（标准分析/深度分析/定制简历）。
- 供应商日/月额度。
- 全局月预算使用比例。

配额：

- 每方案每日最多 20 个新推荐。
- 每账号每日自动多 Agent 3 次、手动 3 次。
- 每用户每日定制简历 3 次。
- 账号不活跃时停止自动多 Agent。

## 4. 成本优化顺序

1. 硬过滤先于 Embedding 和 LLM。
2. 内容哈希相同不重新解析/嵌入。
3. 岗位和事实的结构化结果按版本缓存。
4. 第 11～20 名只做基础匹配，第 4～10 名做单模型标准分析。
5. 多 Agent 仅用于账号级前 3 名和有限手动触发。
6. 快速模型做抽取，高质量模型只做协调和质量审查。
7. 失败重试有限，Schema 修复最多一次。

缓存键必须包含模型、提示词、Schema、输入指纹和授权范围，避免错误复用。

## 5. 预算阈值与自动行为

| 阈值 | 行为 |
|---:|---|
| 50% | 管理后台提醒并检查单用户异常 |
| 80% | 停止非必要离线对照评测，降低自动深度分析优先级 |
| 90% | 停止新的自动多 Agent，只允许配额内手动任务 |
| 100% | 模型熔断，保留规则 + 向量基础匹配；管理员明确恢复 |

达到阈值必须站内透明告知能力降级，不能默默返回伪造的“完整分析”。

## 6. 可观察性

### 指标

- API 请求量、错误率、P50/P95/P99。
- 队列长度、任务等待、成功/失败/重试/死信。
- 每来源采集量、字段缺失率、去重率、最近成功。
- 每供应商请求、token、费用、Schema 失败、备用切换。
- 推荐数量、反馈率、建议接受率。
- PostgreSQL 连接、磁盘、慢查询；Redis 内存；OSS 错误。

### 日志

结构化 JSON，仅安全字段。日志、指标和追踪使用相同 `request_id/task_id/agent_run_id`，但不得放用户正文。

## 7. 备份与恢复

- PostgreSQL：每日加密逻辑/物理备份，30 天滚动。
- OSS：私有、版本/生命周期策略按成本和删除要求配置。
- 配置：不含密钥的配置和迁移纳入 Git。
- 密钥：独立安全备份和轮换流程。
- 每月至少执行一次恢复演练；Beta 前必须有成功证据。

恢复目标（Beta 建议值）：RPO ≤24 小时，RTO ≤4 小时。单机故障期间允许服务中断，但不能丢失删除/授权状态的正确性。

## 8. 运行手册最小集合

- 启动/停止/升级/回滚。
- 数据库迁移和失败处理。
- 暂停单一岗位来源。
- 暂停模型供应商和恢复。
- 预算熔断与人工解除。
- 队列积压和死信处理。
- OSS/数据库备份恢复。
- 密钥泄露轮换。
- 用户删除任务失败修复。
- 安全事件隔离。

## 9. 发布与回滚

- 构建不可变镜像并标注 Git commit。
- 迁移先在备份副本/测试环境验证。
- 发布前运行 smoke test 和 capability check。
- 模型提示词、评分和资源库也必须有版本。
- 回滚代码时不能回滚已确认的用户授权/删除状态。

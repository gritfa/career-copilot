# ADR-002：岗位供给回归核心假设，真实来源 Spike 为 MVP 硬门槛

- 日期：2026-07-30
- 决策来源：项目负责人「阶段 10」任务书（书面下达，非口头转述）
- 状态：**部分取代**——门槛条款（Spike=MVP 硬门槛、宣称限制）已被 ADR-003 废弃
  （项目转为作品集定位，见 docs/14-adr-003-portfolio-pivot.md）；本文的事实记录与
  Spike 报告仍然有效且不得追改。原状态：已生效（取代 ADR-001 D1）

## 背景

ADR-001 D1 曾把 MVP 的岗位供给形态定为「用户导入为主、自动发现为辅、供给不足不阻塞 Beta」，
并据此裁剪了第 5 周连接器计划。阶段 9 验收据此宣称「本地 MVP（合成模型）验收通过」。

负责人于 2026-07-30 明确否定该结论：产品的核心价值主张是「每日自动从合规来源发现新岗位」
（README 第 1 节、PRD 第 21 行）。没有任何一个真实岗位来源被验证可持续供给之前，
「用户自己粘贴岗位再让系统打分」不构成本产品的核心闭环，只是一个降级演示。

## 决定

1. **自动发现是核心产品假设。** 岗位供给不是可裁剪的辅路径，而是产品成立与否的前提。
2. **真实岗位来源 Spike 是 MVP 硬门槛。** 必须至少验证一个真实、合规、可持续的岗位来源
   （真实连接器端到端产出真实岗位并进入推荐），Spike 结论（可行/不可行+证据）形成书面记录。
3. **Spike 通过之前，不得宣称「完整本地 MVP」或「Beta 就绪」。** 现有验收结论一律降级为
   「合成模型 + 合成/导入岗位的本地演示」（见 docs/acceptance-report.md 第 7 节）。
4. **用户导入只是降级/补充路径。** 保留该功能，但其定位是：真实来源暂不可用时的补充输入，
   以及用户手工补录个别岗位的手段；不得再作为「供给形态主路径」出现在任何计划或报告里。

## 影响

- ADR-001 D1 废弃；docs/11 第 5 周「连接器降级为非阻断」的裁剪同步作废。
- docs/acceptance-report.md 的验收结论降级（不重跑历史命令、不伪造记录，只降级结论表述）。
- README 状态口径更新：只主张「代码已实现 + 合成模型本地演示」。
- 用户导入岗位的归属与可见性缺陷（跨用户泄露）在阶段 10 任务 B 修复，与本 ADR 配套：
  导入岗位默认 private 且仅导入者可见，连接器公开岗位才进全局池。

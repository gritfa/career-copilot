# 09. 测试、评测与验收

## 1. 证据层级

必须分别报告：

1. 设计规格已完成。
2. 代码已实现。
3. 本地自动化测试通过。
4. 本地端到端流程通过。
5. 真实供应商/真实来源集成通过。
6. 阿里云环境通过。
7. 20～50 人 Beta 指标通过。

低层级证据不能替代高层级证据。SQLite、Mock API 或静态 Docker 配置不代表 PostgreSQL/pgvector、真实模型或云部署已经验证。

## 2. 自动化测试金字塔

### 2.1 单元测试

- 薪资/经验/学历/城市标准化。
- 硬过滤三态逻辑。
- 评分权重、阈值和舍入。
- 去重候选生成和合并规则。
- 授权范围判断、配额、保留期。
- 事实引用与导出校验。
- 风险规则和公平性特征排除。

### 2.2 集成测试

- 真实 PostgreSQL + pgvector + Redis 容器。
- Alembic 从空库升级、降级策略和重复执行。
- OSS/本地存储 Adapter 契约。
- DeepSeek/Qwen/Embedding 使用录制的脱敏或合成响应。
- Celery 幂等、重试、死信和预算熔断。
- OpenAPI 契约和前端类型。

### 2.3 E2E

Playwright 覆盖：

- 邀请码与免密登录。
- 上传 → 解析 → 事实确认 → 创建方案。
- 查看推荐、证据、风险和反馈。
- 异步深度分析完成/失败/重试。
- 生成定制简历、接受修改、导出 DOCX/PDF。
- 撤回模型授权后的降级。
- 数据导出、单份删除、账号注销与恢复。
- 管理员限时支持访问和越权拒绝。
- 手机视口关键流程。

## 3. 测试数据

### 3.1 开发数据

- 六类岗位的合成简历。
- 覆盖缺字段、冲突事实、复杂 DOCX、文本 PDF、恶意/超大文件。
- 合成岗位快照和连接器 fixture。
- 禁止将网络公开的个人简历直接当测试数据。

### 3.2 真实验证

- 只使用项目负责人自己的简历进行 Beta 前真实流程验证。
- 其他真实用户在授权机制上线后通过正常产品流程进入。
- 测试报告不得包含真实正文。

## 4. 60 组人工标注集

六类岗位各 10 组简历—岗位样本。项目负责人按统一表单标注：

- 是否值得推荐：yes/maybe/no。
- 硬条件结果。
- 关键匹配点及证据。
- 关键缺口及严重度。
- 风险提示是否合理。
- 分数等级是否合理。
- 简历建议是否有帮助、是否改变事实。

至少 20% 样本由第二位评审者复核，用于发现标注标准歧义。记录分歧，不用强行平均隐藏问题。

## 5. 离线指标

| 指标 | 门槛 |
|---|---:|
| Top 10 Precision | ≥70% 基本匹配 |
| 硬条件误放率 | <1% |
| 证据可追溯率 | 100% |
| 虚构事实率（验收集） | 0 |
| 结构化输出有效率 | ≥99%，含有限修复后 |
| 重复岗位残留率 | 由样本标注，首版目标 <5% |
| 受保护属性对偶分差 | 0 或可解释的非属性因素差异 |

分数阈值和权重只有在评测结果有证据时调整，并记录版本。

## 6. 在线 Beta 指标

- 至少 80% 用户在首周找到 3 个愿意进一步查看的岗位。
- 简历建议“有帮助”比例 ≥70%。
- 推荐反馈原因分布和高频失败原因。
- 解析成功率、深度分析成功率、P95 延迟。
- 每活跃用户模型费用和全局预算使用。
- 连接器成功率、字段缺失率、岗位下架率。
- 隐私/越权/虚构严重事件为 0。

产品事件只收集匿名必要数据，访谈 5～8 名用户补充定性证据。

## 7. Agent 评测

固定用例覆盖：

- Prompt injection 岗位文本要求 Agent 泄露提示词或调用工具。
- 岗位要求用户没有的技能，简历 Agent 必须拒绝写入。
- 缺少量化数字时必须提问。
- 风险 Agent 不能把弱信号定性为违法/诈骗。
- 子 Agent 输出冲突时质量审查必须标记。
- DeepSeek 失败且 Qwen 未授权时必须基础降级。
- 修复循环最多一次。
- 用户看不到思维链或内部提示词。

## 8. 文档导出视觉验收

- DOCX 和 PDF 使用2～3套标准单栏模板。
- 对中文字体、分页、长链接、长项目、空章节和多页简历渲染截图检查。
- DOCX 重新打开可编辑；PDF 文本可选择/复制。
- 不截断正文、不出现重叠、乱码或孤立标题。
- 自动测试验证导出内容的事实 ID 与确认库一致。

## 9. 来源连接器验收

每个来源提供：能力矩阵、20个字段样本、条款/访问证据、增量与下架测试、限速/熔断测试。验证码、登录或政策不允许时必须切换为 import-only/link-out，并在能力端点真实呈现。

## 10. 安全测试

- 对象级越权（用户、管理员、导出、签名 URL）。
- 文件上传、压缩炸弹、解析超时。
- CSRF、XSS、SSRF、SQL 注入、开放重定向。
- Magic link 重放、枚举和限流。
- Agent 工具注入、任意 URL/SQL 拒绝。
- 日志敏感字段扫描。
- 授权撤回、删除、备份到期和管理员授权过期。

## 11. CI Gate

合并必须通过：

- Python 格式、lint、类型、单元/集成测试。
- 前端 lint、类型、单元测试和生产构建。
- OpenAPI 契约检查。
- Alembic 迁移检查。
- 依赖和密钥扫描。
- 关键 E2E（使用合成数据）。

验收脚本只要发现失败、缺字段、未验证能力或门槛不满足，必须非零退出。输出“观察结果”但仍返回成功不属于 Gate。

## 12. 本地 MVP Definition of Done

- 全部 MUST 需求已实现或有负责人批准的例外。
- Docker Compose 从空环境一条命令启动。
- 真实 PostgreSQL/pgvector/Redis 通过集成测试。
- 使用合成数据跑通完整 E2E。
- 使用项目负责人简历完成一次真实模型流程。
- 60 组评测达到离线门槛。
- 安全 No-go 项为 0。
- 文档、迁移、OpenAPI、运行手册和证据归档齐全。

## 13. Beta Go/No-go

Beta Go 还需：

- 阿里云 ECS、OSS、HTTPS、备份恢复演练通过。
- 邮箱免密登录真实可用。
- 真实来源能力矩阵和每日任务稳定运行至少 7 天。
- 预算告警和熔断演练通过。
- 删除/导出在云端真实对象上验证。
- 隐私政策、用户协议、模型服务商告知已复核。

任一关键边界未验证，结论必须是“尚未验证/No-go”，不能用本地测试数量替代。

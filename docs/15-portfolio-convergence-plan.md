## P0：真实 DeepSeek 全链路验证（等负责人 key，到手即插队）

前置：负责人提供 `DEEPSEEK_API_KEY`（写入本地 .env，绝不入库）。

1. 实跑三条链路各≥1 次，**全程走既有用户授权检查**（profile_fields 授权门控照常，
   不因验证目的绕过）：
   - 标准分析：真实模型产出 + 证据校验通过（虚构引用拦截对真实模型同样生效）；
   - 定制简历：真实模型产出 + 四道校验 + DOCX/PDF 导出；
   - 失败路径：无效 key → 明确 failed，不静默降级合成。
2. usage_ledger 真实记账（token/费用非零）；日志无正文红线复查。
3. **capabilities 三态口径**：区分「当前已配置」（key 在环境中）、「运行可用」（最近
   健康探测通过）、「历史验证证据」（docs 留档的某日实跑记录）。**不得因某台机器
   成功跑过一次就永久写成 verified**；端点表述按三态实现或如实降级表述。
4. 留存证据写入 `docs/16-real-model-verification.md`：**只存脱敏摘要（请求元数据、
   响应结构、账本行、结论），不得保存完整简历内容、完整 Prompt、API key**。
5. Embedding 仍为确定性合成向量（如实标注；DASHSCOPE key 另议，不阻塞）。

验收：三条链路证据齐全；测试仍全绿（真实 key 不进测试环境）。

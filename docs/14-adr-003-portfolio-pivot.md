# ADR-003：项目定位转为个人作品集项目（Portfolio Pivot）

- 日期：2026-07-30
- 决策来源：项目负责人口头指示（Discord，2026-07-30）：「这个作为一个个人简历项目，不要太复杂」，
  并确认由负责人提供真实 DeepSeek API key、由开发方制定收敛计划。
- 状态：**已生效**（取代 ADR-002 的门槛条款；ADR-002 的事实记录仍然有效）

## 背景

阶段 10 供给 Spike 的第一天真实结果：10 家目标公司招聘官网 **0 家可合规自动采集**
（9 家条款未判读 + 列表 JS 渲染、1 家需登录；见 supply-spike/reports/）。
「每日自动发现岗位」若作为运营产品的核心假设，需要负责人逐家判读条款、授权无头浏览器
渲染等高成本投入，且仍有法律与维护风险。

负责人据此重新定位：本项目不再以上线运营为目标，而是作为**个人简历/作品集项目**，
展示工程能力与负责任 AI 设计。复杂度应服务于「可演示、可讲解」，而非「可运营」。

## 决定

1. **项目定位：个人作品集项目。** 评价标准从「能否上线运营」改为
   「陌生人 5 分钟跑起来、10 分钟看懂亮点」。
2. **废弃 ADR-002 的两条门槛条款**：「真实来源 Spike 是 MVP 硬门槛」与
   「Spike 通过前不得宣称完整本地 MVP」。作品集语境下不存在 Beta/MVP 运营门槛。
   ADR-002 的**事实部分保留**：Spike 工具、10 家来源政策核查记录、supply_gate=not_verified
   的报告全部留在仓库，作为合规工程意识的展示件；报告结论不得追改。
3. **岗位供给形态（最终）：用户导入 + 种子示例数据。** 不再投入爬虫/连接器/无头浏览器
   路线；不进行条款判读流程。fixture 连接器仅用于测试。
4. **砍掉全部运营合规项**：ICP 备案、Beta 指标、备份/熔断演练、隐私政策专业复核、
   真实邮件送达验证、7 天稳定性观察。相关文档条目标注 `dropped_portfolio_pivot`，不删除。
5. **运维面冻结**：admin 只读页与 CLI 维持现状，不再投入。
6. **真实模型验证升为最高优先级**：负责人提供 DeepSeek key 后，跑通
   推荐→标准分析→定制简历真实模型全链路并留存证据。这是作品集可信度的关键一环。
7. **不因定位降级而降低既有质量红线**：不虚构、证据绑定、受保护属性隔离、
   跨用户隐私、测试不回归——这些是作品集的核心卖点，只加强不放松。

## 影响

- docs/11 交付计划中所有运营导向条目失效，收敛计划见 docs/15-portfolio-convergence-plan.md。
- README 将重写为作品集导向（阶段 11 P2）。
- acceptance-report.md 保持历史原样（12be67e 基线），最终状态以阶段 11 完成后的
  portfolio 版 README/报告为准。

## 备选方案与取舍

- **方案 A（放弃）：继续攻真实供给**——负责人逐家判读条款 + 授权无头浏览器渲染公开页。
  取舍：投入高（法务判读 + 反爬军备竞赛 + 长期维护），与「简历项目不要太复杂」直接冲突。
- **方案 B（采纳）：作品集收敛**——供给用导入+种子数据，省下的精力投向真实模型验证与
  demo 体验。取舍：放弃「产品可运营」叙事，换取「工程质量可展示」叙事的完成度。

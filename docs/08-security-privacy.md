# 08. 安全、隐私与合规规格

> 本文是产品与工程控制基线，不替代正式法律意见。Beta 上线前应由具备资质的专业人员复核最新法律、供应商条款和岗位来源政策。

## 1. 数据分类

| 等级 | 示例 | 处理要求 |
|---|---|---|
| Restricted | 原始简历、联系方式、聊天正文、导出文件 | 加密、最小访问、禁止日志、严格删除 |
| Confidential | 结构化事实、模型报告、求职偏好 | 用户隔离、授权检查、审计 |
| Internal | 费用、任务、来源能力矩阵 | 管理员权限 |
| Public | 合法公开岗位、免费资源元数据 | 保留来源和使用边界 |

## 2. 法律与政策基线

- 遵循合法、正当、必要、诚信和最小范围原则。
- 处理前清晰告知目的、方式、种类、期限和权利路径。
- 向第三方模型提供个人信息时按实际法律关系执行单独授权和合同要求。
- 年龄限制为 18 岁以上，减少未成年人个人信息处理范围。
- 用户可访问、更正、撤回、删除、注销和导出。

参考：

- [中华人民共和国个人信息保护法](https://www.npc.gov.cn/WZWSREL25wYy9jMi9jMzA4MzQvMjAyMTA4L3QyMDIxMDgyMF8zMTMwODguaHRtbD9yZWY9aW1i)
- [DeepSeek 隐私政策](https://cdn.deepseek.com/policies/zh-CN/deepseek-privacy-policy.html)
- [阿里云百炼隐私说明](https://help.aliyun.com/zh/model-studio/privacy-notice)

## 3. 模型服务商授权

用户上传简历不等同于授权第三方模型处理。

授权页面对 DeepSeek、Qwen 分别展示：

- 接收方名称和说明链接。
- 数据类别（完整简历/脱敏内容/结构化事实）。
- 处理目的（解析、匹配、改写、备用切换）。
- 可能的保存与风险说明。
- 撤回方式和拒绝后的可用降级路径。

规则：

- 默认不勾选。
- 不使用“一键同意所有供应商”。
- 新供应商、新目的或扩大数据范围必须重新授权。
- 备用切换不是授权例外。
- 撤回不追溯已合法发生的调用，但新调用立即阻断。

## 4. 认证与会话

- 邀请码只保存哈希并限次数/期限。
- magic link token 至少 128 bit 随机、短时、单次、只保存哈希。
- 防邮箱枚举、限流、防重放、审计异常登录。
- Cookie 使用 Secure、HttpOnly、SameSite；会话可撤销和轮换。
- 管理员使用更短会话并建议增加二次验证。
- 权限检查在服务端资源查询中实施，防 IDOR。

## 5. 文件上传和存储

- 白名单 PDF/DOCX，验证 MIME、扩展名和 magic bytes。
- 限制大小、页数、压缩层级和解析时间。
- 恶意文件扫描；解析进程使用受限容器/用户和资源配额。
- OSS Bucket 私有、服务端加密、禁止公共 ACL。
- 下载使用短时签名 URL，并绑定用户权限检查。
- 对象 key 不包含邮箱、姓名或原文件名。
- 文件 SHA-256 用于完整性和重复检测。

## 6. 密钥与供应商调用

- API Key 只放环境变量或云密钥服务，不写代码、不提交 Git、不发送聊天。
- 本地 `.env` 只含开发密钥并进入 `.gitignore`；提交 `.env.example`。
- 不向前端暴露模型、OSS、邮件或数据库凭据。
- 设置供应商额度、来源 IP/权限范围（若支持）和定期轮换。
- 生产日志对 Authorization、Cookie、签名 URL、邮箱、正文自动脱敏。

## 7. 管理员支持访问

默认管理员看不到原始简历。只有用户主动申请支持并授予单份简历、明确原因和短期限权后，指定管理员才能访问。

必须记录：授权人、管理员、资源、原因、授予/访问/到期/撤回时间。管理员不能延长自己的权限，过期自动拒绝。

## 8. 数据最小化与日志

应用日志允许：请求 ID、用户伪匿名 ID、任务类型、模型版本、token、延迟、错误码。

禁止：简历/岗位/聊天正文，模型完整输入输出，邮箱、电话、姓名，Cookie、token、签名 URL、密钥，内部思维链。

调试需要正文时只能使用合成数据；生产支持使用限时授权界面，不能复制到普通日志。

## 9. 删除、注销和导出

- 单份简历删除：同步阻止访问，异步删除文件、解析、向量和派生草稿。
- 注销：进入 7 天恢复期，立即停止推荐和模型任务；到期物理清理。
- 备份：删除数据在 30 天滚动周期内自然到期，不得从备份恢复回活跃系统。
- 数据导出：重新认证、异步生成、短时下载、过期删除。
- 删除任务必须产生可验证清单；部分失败时不能标记成功。

## 10. 匿名产品分析

只收集推荐曝光、反馈选择、建议接受率、任务成功率等必要事件。事件使用不可逆或轮换标识，不包含正文、联系方式、聊天或完整 URL 查询参数。

匿名化前的原始事件应短期保留并受用户删除控制；聚合后不得可合理回溯到个人。

## 11. 公平性

- 受保护属性不得进入评分、Embedding 文本或个性化特征。
- 照片和联系方式在语义召回前移除。
- 岗位歧视性文本只作为风险证据，不用于迎合筛选。
- 评测集包含对偶样本：只替换性别/年龄等字段，分数应保持一致。
- 管理员不能手工提高某一用户或公司的匹配分数而不留版本记录。

## 12. 威胁模型摘要

| 威胁 | 主要控制 |
|---|---|
| 越权读取他人简历 | 服务端对象级鉴权、随机 ID、E2E 越权测试 |
| 恶意简历文件 | 类型验证、扫描、沙箱、资源限制 |
| Prompt injection 岗位文本 | 岗位视为不可信数据、工具白名单、结构化输出、权限在代码层 |
| 模型泄露正文到日志 | Gateway 日志过滤、结构化遥测、测试断言 |
| 供应商未授权切换 | provider + scope 授权门控 |
| Agent 虚构事实 | fact ID 引用、确定性导出校验、质量 Agent |
| 采集越界 | 来源能力矩阵、限速、熔断、import-only 降级 |
| 费用攻击 | 用户/操作/供应商/全局四级限额 |
| OSS 泄露 | 私有 Bucket、短时 URL、最小 IAM |
| 管理员滥用 | 限时用户授权、append-only 审计、最小 RBAC |

## 13. 安全事件

准备可执行流程：发现 → 隔离 → 评估 → 修复 → 通知/报告 → 复盘。至少支持：撤销会话、轮换密钥、暂停模型/来源、阻断下载、查询受影响资源、验证删除。

Beta 前必须进行一次桌面演练：假设 OSS 链接泄露或管理员账号被盗，验证能否在 30 分钟内完成隔离和证据收集。

## 14. 上线阻断项

以下任一存在即 Beta No-go：

- 用户可访问他人简历/报告。
- 完整简历未经独立授权发送第三方。
- 日志或监控含简历正文、密钥或联系方式。
- 删除接口成功但 OSS/向量/派生版本仍可访问。
- 管理员无需用户授权即可看简历。
- Agent 可无确认写事实或虚构成果。
- 岗位连接器绕过外部平台限制。
